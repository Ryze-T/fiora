# Fiora 风险报告固定模板（v1）

> 本模板是 Fiora 的**固定产出契约**：所有 `fiora report` 输出必须符合本规范。
> 模板结构由 `fiora-report` 的模板契约测试锁死（改动结构必须先改本文件再改测试）。

## 版式设计语言

- 马卡龙六色三级梯度（html-beautifier 设计系统）；白底、彩色仅做点缀；
- 严重度色彩映射：CRITICAL=玫瑰粉 / HIGH=蜜桃橙 / MEDIUM=奶油黄 / INFO=天空蓝 /
  正向状态=薄荷绿 / 品牌与导航=薰衣草；
- 卡片体系 card-light（18px/20px 密度基准）、section-divider 渐变线、badge 药丸；
- 单文件离线、零外部资源、打印友好、720px 响应式；
- 离线实现：CSS/JS 全内嵌，字体用系统栈回退；mermaid 渲染器（MIT）仅在报告
  含图时内嵌（无图报告保持轻量）——契约测试断言无 `src="http`/`href="http` 引用。

## 章节结构（顺序固定）

| # | 章节 | 内容 |
|---|---|---|
| 一 | 执行摘要 | 统计卡（严重度/真漏洞/存疑/误报/链）+ 严重度分布条 + 核心结论 |
| **二** | **RCE 攻击面（最高优先）** | **审计最高优交付**：全部可导致代码执行的发现（直接 RCE / 升级路径）+ RCE 利用链，按「离执行有多近」分层（🔴 直接 RCE → 🟠 升级路径 → 🟡 链式跳板）；红金配色警示 |
| 三 | 漏洞链路 | 按链严重度降序；交互 SVG 链路图（点节点跳详情）+ 步骤 + 影响 |
| 四 | 漏洞详情 | **严格排序**：CRITICAL→HIGH→MEDIUM→LOW→BUG，同级 TP 先于存疑；分组标题；筛选器 |
| 五 | 负向结论 | 被反驳候选 + 反驳理由（可审计） |
| 六 | 覆盖率附录 | 入口面覆盖率 + 文件/候选统计 + 入口清单 |
| 七 | 方法说明 | 分工哲学 / 判定协议 / 证据等级 / 防漏纪律 |

## RCE 提取规则（确定性）

RCE 判定（任一命中即提取）：category ∈ {rce, code-injection, insecure-deserialization, cmdi}
或 title/impact 含「RCE / 代码执行 / 执行任意 / 反序列」。分层：
**直接 RCE**（输入直达代码执行）→ **升级路径**（写入/加载/覆写后可执行）→ **链式跳板**
（本身非 RCE 但构成 RCE 链的入口，如 SSRF 打内部反序列化面）。
RCE 相关链 = 步骤含 RCE 发现的链，随专章展示。

## 发现卡片固定结构（顺序固定）

```
标题行：[严重度徽章] #N 标题 · file:line · [结论徽章]        （可折叠，CRITICAL/HIGH 默认展开）
├─ 问题     短句分点（· 每点一行，每句 ≤25 字，先结论后细节）
├─ 影响     红标独立区块，短句分点（攻击者能做什么、危害量级）
├─ 数据流   entry → … → sink 一行式（可选）
├─ 代码上下文（折叠）   发现位置 ±N 行，行号 + 暗色代码块
├─ 证据链（默认展开）   entry/hop/source 彩色标签逐跳 + 断链警示 + 证据等级
├─ 六问反驳记录（折叠）  六问表格 + 备注
├─ 判定     结论 + confidence + 推理（短句分点）
├─ PoC（复现包）        绿标区块直接可见：前置条件 + 请求 + 预期/实际 + 状态徽章；缺失显式告警
└─ 审计溯源             agent / model / thinking / run id
```

## 文风契约（所有可读文本）

1. **中文**；代码标识符/路径/命令原样；
2. **短句分点**：每点一行、每句 ≤25 字、先结论后细节；禁长句大段落；
3. 标题 ≤30 字：「哪里、什么、后果」一句话；
4. 事实、判定结论、代码坐标不可改写或省略。

## 交互契约

- 粘性导航（六章节锚点）+ 全部展开/收起；
- 发现筛选器（严重度/存疑）；
- 链路图节点点击跳转并自动展开目标卡片；
- `<details>` 渐进增强：无 JS 也可完整阅读。

## 复现与验收

模板契约测试：`cargo test -p fiora-report`（结构、排序、区块、离线性全部断言）。
